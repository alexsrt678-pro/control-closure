# Challenge the Control Architecture

The claim is simple: the public F1-F9 architecture is sufficient as a functional control frame for AI-agent systems.

If you think it is not, bring a concrete counterexample.

## A useful counterexample has four parts

1. **System or mechanism** - what exactly are we discussing?
2. **Observed action or transition** - what does it actually do?
3. **Why F1-F9 is insufficient** - which necessary function or relationship is missing?
4. **Primary evidence** - paper, technical documentation, implementation, benchmark, incident report, or reproducible behavior.

A new product name, a new acronym, or a different implementation of an existing function is not by itself a new function.

## Possible outcomes

A review can end in one of four public outcomes:

- **Fits** - the mechanism is already represented by an existing public function.
- **Fits at deeper resolution** - the mechanism is a subfunction or obligation inside an existing function.
- **Insufficient evidence** - the claim cannot yet be distinguished from a naming or documentation difference.
- **Architecture change required** - the counterexample genuinely requires a new function or a fundamentally different relationship.

If the fourth outcome occurs, it should be published as such. The point of the challenge is to expose where the architecture fails, not to defend it rhetorically.

## Public vs private

Public systems with public evidence can be discussed openly.

Private company architectures, confidential agent stacks, and implementation work belong in a private review or pilot. The public challenge is not a mechanism for extracting private implementation design for free.
